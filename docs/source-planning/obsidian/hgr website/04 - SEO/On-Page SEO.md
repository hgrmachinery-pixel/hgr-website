# HGR On-Page SEO Standards

## Scope

Practical content and template requirements for V1; these apply the human-approved research-informed themes without selecting a framework or inventing keyword metrics. Final public copy still needs factual review and approval. Sources: [[02 - Website Specification/Sitemap]], [[02 - Website Specification/Used Excavators]], [[02 - Website Specification/Individual Machine]], [[02 - Website Specification/Admin System]], [[03 - Content/Website Copy]] and [[04 - SEO/Keyword Strategy]].

## Titles and meta descriptions

Give each public page a concise, descriptive title reflecting its distinct purpose. Include HGR where useful; avoid a repeated chain of location/keyword variants. Machine titles should distinguish actual units using available verified information. Do not use an unknown year, invented condition claim or fake price.

Write a useful summary for each page's meta description. Templates may use verified structured fields, but omit unavailable fields cleanly. Sold-page descriptions must not imply the unit remains for sale. Review display length and readability during implementation; no fixed character count guarantees how a search engine displays a result.

Title pattern direction: [Year where known] [Brand] [Model] Used Excavator | HGR Equipment Resources. Keep it natural and concise; use only known identity. Final wording follows approved qualitative themes and copy approval, not invented volume rankings.

## Headings and introductions

Use one clear primary H1 as the project editorial standard. Individual machine headings should naturally identify year where available, brand, model and machinery type. Structural example only: 2018 Komatsu PC200-8 Used Excavator. Omit an unknown year; the example is not inventory. Machinery Services uses the specified Heavy Machinery Services heading; its navigation name remains Machinery Services.

Use H2 for major sections and H3 for genuine subsections. Do not select heading levels just to change font size. Keep introductions short so inventory, photographs, prices and contact actions appear promptly. Helpful supporting copy should not become a wall of SEO text above the machines.

Use the human-reviewed CTA vocabulary in Website Copy. Homepage Available Excavators contains only Published + Available units (approximately 3–6, fewer if necessary), and the final homepage conversion section prioritises WhatsApp HGR, Call HGR, then optional Send Enquiry. Other example headings remain subject to final copy approval.

## URLs and names

Retain established core routes: /, /used-excavators, /excavator-rental, /machinery-services, /lubricants, /about and /contact.

Individual route /used-excavators/[machine-slug] remains proposed. [DEFERRED] final slug generation, collision resolution and canonical-host conventions. Require readable stable URLs, unique physical-unit identity and automatic conflict handling. Do not change a URL just because the price or availability changed.

Use actual machine identity including year where available, brand, model and machinery type for the detail-page name/heading. Cards may retain concise Brand + Model with year nearby. Do not append a repetitive string of sales keywords. Example machines in specifications are not approved inventory.

## Descriptions and structured content

Use labelled factual specifications, verified Machine Location where available, an optional useful description, actual photographs, status, price mode and video where supplied. Serial Number is optional: store internally with separate optional public display. Do not expose an internal-only serial in page text, URLs, metadata, schema, alt text, shared links or analytics. Omit empty optional fields instead of inserting 0, Unknown or fabricated values. Keep listing/publishing status separate: Available/Reserved/Sold is not Draft/Published.

Describe material condition honestly. A similar model is not a reason to reuse another unit's hours, price or photographs. Machine ID should connect admin, URL, enquiry and measurement; public ID display remains [DEFERRED].

## Images and alt text

Describe the meaningful image and view concisely, using known brand/model where useful. Example structure: [Brand] [Model] used excavator, left side. This is not a claim about actual stock.

Avoid repeated keyword lists or alt text that invents condition. Decorative imagery should have an appropriate empty alternative. Controls in galleries need meaningful labels independent of image descriptions. Keep text readable outside images.

Follow [[05 - Assets/Photography & Video]] for real-image integrity, responsive images and watermarks.

## Links, breadcrumbs and CTAs

Use descriptive links to inventory, related machines, Contact and relevant business pages. Do not force identical keyword anchors everywhere. All published units must be discoverable through ordinary links.

Machine breadcrumb direction: Home → Used Excavators → machine name. Home in a breadcrumb does not require a Home item in primary navigation.

Keep View Machine for cards, WhatsApp About This Machine for primary unit enquiries, and clear Call HGR / Send Enquiry alternatives. Arrange a Viewing may open WhatsApp for the confirmed Klang-yard viewing flow; appointments are preferred and machine location must be checked before visiting. Machine-specific messages must include the actual unit and URL. Arrange a Viewing may use: Hi HGR, I'd like to arrange a viewing for the [MACHINE NAME]. [MACHINE PAGE URL]. Insert actual public machine information; no online appointment system is required. The general navigation remains Used Excavators, Rental, Machinery Services, Lubricants, About, Contact; logo links home.

## Sold and reserved listings

Maintain permanent useful pages. Display status in text, update metadata and any schema to match, and direct sold-unit visitors toward available alternatives or a similar-machine enquiry. Never advertise Sold as Available to attract clicks.

Do not repurpose a sold unit's page for a different physical machine. Do not automatically redirect all sold URLs to inventory.

## Marketplace links and canonical identity

Mudah remains an acquisition channel. Where current marketplace policy permits, its listing links should open the corresponding HGR physical-machine page with richer genuine information/media. Keep the URL stable after publication and sale.

Permitted campaign parameters identify acquisition, not separate SEO pages. Use consistent internal links and canonical identity for the clean public URL. Tracking naming/implementation remains [DEFERRED]. Do not put internal-only serial numbers in tracking parameters.

## Duplicate content, pagination and filters

Use one intended page per meaningful topic. Avoid empty brand/location pages, copied product descriptions and duplicate campaign pages without a clear purpose.

[DEFERRED] pagination versus Load More and parameter policy. No infinite scroll for V1 per Used Excavators. If pagination is used, distinct pages need their own URLs and appropriate canonical identity; do not canonicalise all pages to page one. A Load More interface must still expose discoverable item/page links. See [Google pagination guidance](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading).

Do not let arbitrary search/filter/sort combinations become a large indexable catalogue. Final indexing/crawl rules belong in Technical & Local SEO. Future curated category pages require unique value, sufficient inventory/real offerings and evidence from search, Ads and enquiries. No automatic model/category, location or state/city rental pages and no blog are required for V1.

## Future categories and languages

[FUTURE] machinery divisions, individual lubricant pages and translated pages must use their own relevant content. Do not force used-machine fields onto a new product model.

English is V1. Plan an expansion path for separate language content and metadata; locale URL design and translation relationships are [DEFERRED]. Do not generate empty translated pages or publish mixed-language keyword lists.

## Update and approval checklist

- [ ] Apply approved research-informed themes and confirm page intent/facts; distinguish uncollected quantitative metrics.
- [ ] Verify business and machine facts, images, price mode and status.
- [ ] Review unique titles/descriptions and clear heading hierarchy.
- [ ] Check canonical route, breadcrumbs and working internal links.
- [ ] Confirm contact CTAs and machine context.
- [ ] Check useful alt text and mobile readability.
- [ ] Remove placeholders and unsupported claims.
- [ ] Review changed status/price across page, metadata and sharing previews.
- [ ] Obtain HGR copy approval and keep routine updates manageable in admin.

Default SEO generation must support non-technical publishing. Advanced overrides are optional, not a requirement that the owner manually write every metadata field.
