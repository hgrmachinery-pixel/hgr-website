<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Payload route → PostgreSQL state transition | Concurrent or stale requests can publish a changed revision without locking/current-state checks. |
| Authenticated user → roles/permission resolver | Stale claims or request data may attempt to forge publish authority. |
| Application → public preview bytes | Direct object URLs, optimizer or shared cache may bypass wrapper authorization. |
| Payload/GCS adapter → anonymous object access | Handler or ACL behavior may expose private originals or pending derivatives. |

## STRIDE Threat Register (ASVS L1; block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Elevation of privilege / tampering | Publish transition and document APIs | high | mitigate | Reload current Roles, lock parent, validate exact revision/digest/review/readiness and deny direct field/API/Local API mutation. |
| T-03-10 | Repudiation / tampering | AssetAuditEvents | high | mitigate | Server-stamped immutable events, deny update/delete in Payload access/hooks, no cascades, same request transaction; Plan 04 adds the reviewed PostgreSQL trigger. Do not claim superuser resistance. |
| T-03-11 | Information disclosure | Preview route, Payload/GCS handler, optimizer/cache | high | mitigate | Permission-check wrapper and bytes, app-stream selected revision, private no-store including range/denial, deny direct object URLs; photo and document bytes remain disabled until actual approved handler test passes in Plan 04. |
| T-03-SC | Tampering | npm dependency installation | high | mitigate | No package installation; retain installed stack and run package-legitimacy gate before any future dependency addition. |
