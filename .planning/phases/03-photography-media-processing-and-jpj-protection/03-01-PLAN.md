<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Staff browser → Payload upload | Untrusted filenames, MIME claims, file bytes, machine IDs and category values enter the app. |
| Payload → Sharp | Attacker-controlled file bytes reach a native image parser and transformer. |
| Public request → Payload media/static file handler | Anonymous requests may attempt to fetch source masters, unapproved derivatives or files for unpublished machines. |
| App → PostgreSQL/GCS | Schema and media state use configured external services; GCS objects remain private. |

## STRIDE Threat Register (ASVS L1; block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information disclosure | MachineMedia API/static file access | high | mitigate | Staff-only masters; per-record derivative authorization checks current machine identity, relationship, publication, processing and approval on every request; private GCS; no-store responses; public delivery defaults disabled until the actual installed Payload/GCS handler passes the Plan 03-03 live check. |
| T-03-02 | Denial of service / tampering | Photo upload and Sharp processing | medium | mitigate | Allowlisted image formats, validated configurable byte limits, bounded per-file concurrency, separate per-file failure state and synthetic batch tests. |
| T-03-SC | Tampering | npm dependency installation | high | mitigate | No package installation task; retain the approved dependency tuple and require the package-legitimacy gate before any later addition. |
</threat_model>
